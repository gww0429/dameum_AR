# dameum_AR v2

전시회용 웹 AR 서비스. 관람객은 `index.html`(모바일), 설정 담당은 `admin.html`(PC 1280px 이상)을 씁니다.
카메라는 HTTPS에서만 켜지므로 GitHub Pages에 올려서 씁니다. 외부 CDN 없이 `lib/`의 내장 라이브러리만 씁니다.

## v1.2 → v2 올리는 법 (이미 v1.2를 배포해 쓰고 있을 때)
v2는 **코드 파일만 교체**합니다. 설정 페이지로 발행한 실제 콘텐츠(`config.json`, `assets/`)는 그대로 둡니다.
v2 코드는 v1 형식(schema 1) `config.json`을 읽을 때 자동으로 v2로 바꿔 씁니다(파일은 고치지 않음).

### ① GitHub에 올릴 파일 (바뀌었거나 새로 생긴 코드만, 11개)
| 파일 | 상태 |
|---|---|
| `index.html` | 수정 |
| `admin.html` | 수정 |
| `README.md` | 수정 |
| `css/app.css` | 수정 |
| `css/admin.css` | 수정 |
| `js/app.js` | 수정 |
| `js/admin.js` | 수정 |
| `js/missions.js` | 수정 |
| `js/theme.js` | 수정 |
| `js/config.js` | **새 파일** (v1 → v2 config 변환, 관람객·설정 공용) |
| `js/imageEditor.js` | **새 파일** (설정 페이지 이미지 편집기) |

- 저장소의 같은 경로에 덮어씁니다(폴더 구조 그대로).
- 다시 올리지 않아도 되는 파일(v1.2와 내용이 같음): `js/ar.js`, `js/convert.js`, `js/github.js`, `js/haptics.js`, `js/storage.js`, `lib/mindar/` 전체, `lib/three/` 전체, `.nojekyll`.

### ② GitHub에서 지울 파일 (v2에서 안 쓰게 된 것)
| 경로 | 이유 |
|---|---|
| `js/placer.js` | 「내 공간에 놓기」 삭제 |
| `lib/model-viewer/` 폴더 전체 (`lib/model-viewer/model-viewer.min.js`) | 「내 공간에 놓기」 삭제 |

- 지우지 않아도 사이트는 동작합니다(v2 코드가 부르지 않음). 저장소 정리를 위해 지웁니다.
- 예전 로고·대표 이미지(`assets/brand/logo.*`, `assets/brand/hero.*`)는 손으로 지우지 않아도 됩니다. 설정 페이지에서 다음에 발행할 때 자동으로 정리됩니다.

### ③ 올리면 안 되는 파일
| 경로 | 이유 |
|---|---|
| `config.json` | 이 폴더의 것은 로컬 테스트용(v1 형식 데모)입니다. 올리면 발행한 실제 설정을 덮어씁니다. |
| `assets/` 폴더 전체 | 로컬 테스트용 포스터·인식 파일·임시 모델입니다. 올리면 발행한 실제 포스터·모델·사은품 이미지·인식 파일을 덮어씁니다. |
| `serve.ps1` | PC 테스트용 로컬 서버입니다. |

### 올린 뒤 순서
1. 1~3분 뒤 폰으로 관람객 화면을 엽니다. v1 config 그대로도 새 홈(버튼 두 개)·새 미션 카드로 열리는지 확인합니다.
   - 브라우저가 옛 파일을 기억하고 있으면 새로 고침을 한 번 합니다. HTML이 CSS·JS를 `?v=2` 주소로 부르므로 옛 JS와 새 JS가 섞이지 않습니다.
2. PC에서 `admin.html`을 열고 헤더의 「사이트에서 불러오기」를 누릅니다(v1 설정이 v2로 바뀌어 들어옵니다).
3. 「홈 꾸미기」에서 배경색·홈 이미지를, 포스터 「미션」 탭에서 안내 문구를 확인합니다.
4. 「GitHub에 바로 발행」을 누릅니다. `config.json`이 v2 형식(schema 2)으로 저장되고, 안 쓰는 로고·대표 이미지가 정리됩니다.

## v2에서 바뀐 점
- 관람객 홈: 배경색 + 홈 이미지 1장 + 「선물 상자」「AR 시작하기」 버튼만. 로고·제목·소개·대표 이미지·포스터 목록·카메라 안내 줄은 없어졌습니다.
- 미션 카드: 미션 안내 문구 + 진행만 보입니다(설명글·포스터 이름 없음). 미션 「없음」 포스터는 카드 없이 3D만.
- 미션 성공: 카드가 내려간 뒤 사은품 시트 → 「확인」 → (스탬프 투어 완주면 완주 시트 → 「확인」) → 선물 상자. 선물 상자의 「‹ AR」로 스캔 화면에 돌아갑니다.
- 「내 공간에 놓기」 삭제. 3D가 뜨는 위치는 설정 페이지 「3D 배치」에서 정합니다.
- 설정 페이지: 홈 이미지·사은품 이미지·미션 아이콘은 이미지 편집기로 규격에 맞춰 저장합니다(홈 3:4 1080×1440, 사은품 1:1 800×800, 아이콘 1:1 256×256 PNG). 편집기에 넣은 원본은 그 PC 브라우저에만 남고 발행되지 않습니다. 포스터(인식용) 이미지는 편집하지 않고 원본 그대로 저장합니다.
- 포스터 이름은 선물 상자·직원 확인 화면에서 관람객에게 보입니다. 관람객이 봐도 되는 이름으로 지어 주세요.

## 폴더
| 경로 | 내용 |
|---|---|
| `index.html` | 관람객 웹앱 (홈 · AR · 선물 상자 · 직원 수령) |
| `admin.html` | 설정 페이지 (홈 꾸미기 · 포스터 · 직원 코드·스탬프 투어 · 발행 설정) |
| `js/config.js` | config 형식 변환(v1 → v2). 관람객 앱과 설정 페이지가 함께 씁니다 |
| `js/imageEditor.js` | 설정 페이지 이미지 편집기 |
| `config.json` | 행사 설정 한 개 (저장소 1개 = 행사 1개). 이 폴더의 것은 로컬 테스트용 |
| `assets/` | 포스터·모델·사은품 이미지·홈 이미지, `targets.mind`(인식 파일), `placeholder.glb`(임시 모델). 이 폴더의 것은 로컬 테스트용 |
| `lib/` | MindAR 1.2.5, three 0.160(+ 압축 해제 도구·형식 변환 로더) |
| `.nojekyll` | GitHub Pages가 파일을 가공하지 않게 하는 빈 파일 |
| `serve.ps1` | PC 테스트용 로컬 서버 (저장소에 올리지 않습니다) |

## 처음 올리는 법 (새 저장소에 처음 배포할 때만)
1. 이 폴더 안의 내용(`index.html`, `admin.html`, `config.json`, `.nojekyll`, `README.md`, `css/`, `js/`, `lib/`, `assets/`)을 저장소 **루트**에 올립니다.
   - 웹에서 끌어다 올릴 때 `.nojekyll`이 빠지지 않았는지 확인합니다(윈도우 탐색기에서 숨김 파일로 보일 수 있습니다).
   - 이미 행사 콘텐츠를 발행한 저장소라면 이 절이 아니라 위의 「v1.2 → v2 올리는 법」을 따릅니다.
2. 저장소 Settings → Pages → Source를 `Deploy from a branch`, 브랜치 `main` / 폴더 `/ (root)`로 둡니다.
3. 1~3분 뒤 `https://<계정>.github.io/<저장소>/` 에서 관람객 화면, `…/admin.html` 에서 설정 페이지가 열립니다.

## 설정 페이지로 발행
1. PC 브라우저로 `admin.html`을 엽니다.
2. 처음이면 「발행 설정」에서 접근 키(토큰), 저장소(`owner/repo`), 브랜치 `main`을 넣고 「연결 확인」을 누릅니다. 이 값은 그 PC 브라우저에만 저장됩니다.
3. 기존 행사를 고칠 때는 헤더의 「사이트에서 불러오기」, 새 행사는 ⋯ → 「새 프로젝트」(빈 상태로 시작, 이전 행사 파일·편집기 원본은 남지 않음).
4. 홈 꾸미기 → 포스터 등록·편집(오른쪽 휴대폰 미리보기로 확인) → 직원 코드·스탬프 투어를 정합니다. 편집 내용은 그 PC 브라우저에 자동 저장됩니다.
5. 「GitHub에 바로 발행」을 누르면 필요할 때 인식 파일을 먼저 만들고(변환 중에는 탭을 옮기지 마세요), 바뀐 파일만 커밋 1개로 올립니다. 1~3분 뒤 폰으로 확인합니다.
   - 더 이상 쓰지 않는 `assets/posters|models|gifts|brand` 파일은 같은 커밋에서 지워집니다.
   - 처음 배포본의 직원 코드는 데모용입니다. 실제 행사 전에 「직원 코드·스탬프 투어」에서 새로 정해 주세요(원문은 어디에도 저장되지 않고 해시만 저장됩니다).

## 접근 키(토큰) 발급
1. GitHub 로그인 → 오른쪽 위 프로필 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
2. Token name 아무 이름, Expiration은 행사 기간에 맞게.
3. Repository access: **Only select repositories** → 이 서비스를 올린 저장소.
4. Permissions → Repository permissions → **Contents: Read and write** (Metadata: Read-only는 자동으로 붙습니다).
5. Generate token → 나온 값을 설정 페이지 「발행 설정」의 접근 키 칸에 붙여 넣습니다. 이 값은 다시 볼 수 없으니 필요하면 새로 발급합니다.
6. 다른 사람과 같이 쓰는 PC라면 작업 후 「발행 설정」 → 「키 지우기」를 누릅니다.

## PC에서 테스트
```
powershell -ExecutionPolicy Bypass -File serve.ps1
```
- `http://localhost:8795/` 관람객 화면 (localhost는 HTTPS가 아니어도 카메라가 켜집니다)
- `http://localhost:8795/admin.html` 설정 페이지
- 미리보기 모드(카메라 없이): `?preview=1`(1번 포스터 인식 후 화면), `?preview=home`, `?preview=box`, 뒤에 `&reset=1`을 붙이면 미리보기 선물 상자를 비웁니다. 미리보기 저장은 실제 선물 상자와 따로 저장됩니다. 미리보기에서 사은품 「확인」을 누르면 미리보기 선물 상자로 가고, 「‹ AR」을 누르면 「인식 후」 장면을 처음부터 다시 보여 줍니다.

## 알아 둘 점
- 3D 모델 형식
  - 관람객 화면은 GLB만 씁니다. Draco·KTX2(Basis)·Meshopt로 압축한 GLB도 읽습니다(해제 도구는 `lib/three/addons/libs/`에 들어 있어 외부에서 받지 않습니다).
  - 설정 페이지에는 GLB 말고도 glTF(.gltf + .bin·텍스처), FBX, OBJ(+ .mtl·텍스처), STL, DAE(Collada), 3DS, PLY를 올릴 수 있습니다. 올릴 때 브라우저에서 GLB로 바꿔 저장합니다(애니메이션 유지). 텍스처가 따로 있으면 모델 파일과 함께 여러 개를 선택하거나 zip 하나로 묶어 올립니다.
  - USDZ는 받지 않습니다(아이폰 전용 형식이라 웹에서 안정적으로 읽을 수 없습니다).
  - 크기 기준은 저장되는 GLB에 적용합니다. 15MB를 넘으면 경고, 50MB를 넘으면 올릴 수 없습니다.
- 3D 제작 업체에 요청할 때: **GLB(glTF 2.0 바이너리) 한 파일, 5MB 안팎**, 텍스처 2048px 이하를 권장합니다. 용량이 크면 Draco(메시)·KTX2(텍스처) 압축을 요청하세요. 다른 형식에서 바꾼 GLB는 재질이 단순해지거나 용량이 커질 수 있습니다.
- 이미지 규격: 홈 이미지 3:4 1080×1440(최대 1.5MB), 사은품 이미지 1:1 800×800(최대 500KB), 미션 아이콘 1:1 256×256 PNG(최대 200KB). 배경을 투명으로 두면 PNG, 색으로 채우면 JPG(아이콘은 언제나 PNG)로 저장됩니다. v1에서 올린 이미지는 규격과 달라도 그대로 쓰이며, 「편집」으로 맞출 수 있습니다.
- 선물 상자는 관람객 폰 브라우저에 저장됩니다. 브라우저를 바꾸거나 데이터를 지우면 사라집니다. v1.2에서 받은 선물은 v2에서도 그대로 보입니다.
